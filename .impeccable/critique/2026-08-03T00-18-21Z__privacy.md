# Critique — trust & error surfaces: /privacy, /terms, /embeds/terms, 404s, error boundary, loading skeleton

Anchored sweep unit, register: **product** (earned familiarity — would a Linear/Stripe-fluent user trust it). Evaluated 2026-08-02 against the running dev server (next dev / Turbopack, localhost:3000, branch main) with Playwright (repo's own @playwright/test, headless Chromium) at 1280x900 and 390x844, plus 320 and 768 spot checks, in EN and ES. Appendix surfaces: OG cards (home + bill, both locales), webmanifest (both locales), /feed/whats-moving.xml.

**Method caveats (flagged per no-guessing rule):** (1) The server is a dev build — request counts/bytes are dev-mode numbers (~4.1MB, Turbopack chunks) and were NOT used to score performance; no prod build was run because `.next` belongs to the running server and the unit forbids repo writes. (2) The error boundary could not be triggered from outside: localStorage poisoning of every key plus planted garbage did not crash /record, /, or a bill page (lib/local.ts guards held) — error.tsx is assessed from source + token analysis only. (3) The loading skeleton never appeared in three driven slow-navigation attempts (5s-delayed target, EN+ES, both viewports) — reported as a finding below, needs prod confirmation. (4) `/%ff` returns Next's built-in 400 page, so the root 404 was exercised via /nonexistent-xyz and /en/nonexistent (307 → /nonexistent) instead.

## Headline discovery

**The reviewed, bilingual, in-layout 404 (`app/[locale]/not-found.tsx`) is dead code.** All four 404 shapes tested — `/bills/nope`, `/es/bills/nope`, `/nonexistent-xyz`, `/en/nonexistent` — render the bare root fallback (`app/not-found.tsx`): English-only, `lang="en"`, no header, no footer, no skip link, no `<title>`, system font stack. Mechanism confirmed in source: `app/[locale]/bills/[id]/page.tsx:56` sets `dynamicParams = false` (unknown ids are rejected at routing level, never reaching the page's `notFound()` at :116), and there is no `[...rest]` catch-all under `app/[locale]/`, so unmatched paths — and the locale layout's own `notFound()` at `app/[locale]/layout.tsx:82` — all resolve to the root boundary. The locale file's own doc comment (:5-8, "a visitor who mistypes a bill slug is still on Oravan") describes behavior that does not exist. A Spanish user who mistypes any URL gets an unannotated English page with no navigation — a runtime violation of the bilingual-parity hard rule. Borderline P0; filed as the top P1 because the fallback is functional (correct 404 status, noindex, working Go-home CTA at 121x52, live token colors).

## Findings (P0 none · P1 2 · P2 5 · P3 6)

**P1 — Locale 404 never renders; every 404 is the bare English root fallback.** Evidence above. Fix: add `app/[locale]/[...rest]/page.tsx` calling `notFound()` so unmatched paths under a valid locale render `app/[locale]/not-found.tsx` inside the layout (header/footer/lang survive); `/bills/nope` then falls through `dynamicParams=false` to the catch-all. Effort S.

**P1 — "[FOUNDER: fill]" is live on the public page** at /embeds/terms §9 Governing law, both locales (messages en/es `embedsTerms.lawBody`; screenshot). Deliberate placeholder per the page comment, but jurisdiction is a decision only Colby can make, and until then a literal scaffold string is public. Owner decision needed. Effort S once decided.

**P2 — No pending indication on slow navigations; loading.tsx never fired.** Three driven attempts (real link click to /privacy with all matching requests delayed 5s; EN+ES; 1280+390): user stays parked on the old page, no skeleton, no spinner (results2.json loading@*: present:false). Dev-mode caveat — verify on a prod build; if it reproduces, `app/[locale]/loading.tsx` is dead UI on the nav path. Effort M to diagnose.

**P2 — Privacy page dead-ends its own commitments.** `app/[locale]/privacy/page.tsx:26` renders p1,p2,p3,p7,p4,p5,contact — but `privacy.builtBy` + `privacy.repoLinkLabel` (written, translated, reviewed in both message files) are wired to nothing, so "built in the open — every line of code is inspectable" ships with no repo link and "Questions?" with no contact channel (hello@oravan.org is live); "your civic record page has a one-tap button" has no link to /record. Effort S.

**P2 — Root 404 has no `<title>` and no brand mark.** `app/not-found.tsx` supplies its own `<html>` with no metadata; tab and history show a bare URL, and the page carries zero Oravan identity beyond the green button. Add a metadata export/title + the wordmark treatment the OG cards use. Effort S.

**P2 — Embeds-terms doc-foot links miss the house touch-target floor.** `app/[locale]/embeds/terms/page.tsx:109-115`: standalone (non-inline) links at 22px height in a `flex-col` that also stretches them to the full 496px column. Passes WCAG 2.5.8 AA only via the spacing exception; fails DESIGN.md's own 44px rule for non-inline links. `min-h-11 self-start inline-flex items-center`. Effort S.

**P2 — ES error-boundary copy is machine-drafted, never native-reviewed** (`app/[locale]/error.tsx:19-22`, standing gap in docs/es-script-spotcheck.md). The crash screen is the worst place for unreviewed Spanish. Needs the reviewer, not code. Effort S, owner/reviewer decision.

**P3 — Legal-doc h1 register inconsistency** (h2-loud vs h1-bill across sibling documents) — taste call. **P3 — Feed has no browser presentation**: no `xml-stylesheet` (raw XML wall — screenshot), no `atom:link` self-ref; an XSL sheet would make the feed URL its own tenant-facing landing page. Scope call. **P3 — hello@oravan.org in §10 is plain text**, not `mailto:` (no `a[href^=mailto]` on page). **P3 — OG AI-marker radius 6px** off both shape tokens (should be 3, the stamp scale). **P3 — `/%ff` serves Next's unbranded default 400** ("400: Bad Request") — platform behavior, recommend accepting. **P3 — DESIGN.md:236 still claims AI content is "human-reviewed before it drives a call"** — the exact claim the constitution amended away on 2026-07-25 (CLAUDE.md); off-surface doc drift spotted during this unit, cheap to fix.

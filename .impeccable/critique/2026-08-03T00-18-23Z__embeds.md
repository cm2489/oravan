## Findings

### P1 — Color-drag remounts the preview iframe once per input event (the July remount finding is NOT fixed on main)
components/EmbedConfigurator.tsx:544 (`onChange` → setAccentInput), :288–306 (`previewSrc` memo includes `accent`), :720 (`key={previewSrc}`). Browser evidence: a 10-event input burst on `#oravan-accent` produced **10 full `/embed/rep-lookup` document loads** and the iframe DOM node was **replaced** (element identity check false). A real macOS color-picker drag fires continuously → dozens of SSR renders + visible white-flash remounts per drag. A single discrete change correctly costs 1 reload. No debounce/useDeferredValue exists in this file on any branch (checked history). Fix: debounce the accent feeding previewSrc (~250ms) or push theme changes into the same-origin iframe via postMessage/CSS vars without navigation. NOTE (no-guessing flag): my unit brief said this "was fixed" — I could not find any commit fixing it, and the behavior reproduces on main today; if the fix lives somewhere I couldn't see, the verification above supersedes it.

### P2 — Mobile: selecting a bill/knob gives no feedback that the preview updated
At 390x844 the stacking is controls-first; after tapping a bill the preview iframe sits at y≈2044 (offscreen; snippet further). Only signal near the tap is the small selected-bill echo. A Stripe-fluent user gets no confirmation the preview/snippet exist below. Consider a "See preview" anchor, auto-scroll on selection, or a sticky mini-preview. decisionNeeded.

### P2 — "Showing 25 of 2568 matches" mislabels the corpus as the match count
EmbedConfigurator.tsx:462–464 passes `total: bills.length` (whole corpus) into `billResultsNote`; searching "water" shows "Showing 25 of 2568 matches" though 2568 is not the match count. Both locales. Fix: pass the filtered pool length before `.slice(0, MAX_RESULTS)`, and reword the unfiltered case ("of 2,568 bills").

### P2 — Bill search fails label-in-name (WCAG 2.5.3)
EmbedConfigurator.tsx:420–427: visible `<label for>` says "Choose a bill" but `aria-label="Search bills"` replaces it as the accessible name; voice-control users saying the visible label miss. Fix: drop the aria-label (the label already names it) or align the strings. Same in ES.

### P2 — Mockup's fake headlines are real H2/H3s in the /embeds document outline
components/embed/HostPageMockup.tsx:114 (newsroom h2), :131 (library h2), :152 (advocacy h2), :165 (generic h2). Screen-reader heading nav reads "City council weighs the bills that shape this session" as a top-level section of Oravan's own page, between "Live preview" (h3) and "Copy this snippet" (h3) — the outline recorded was H1 H2 H3 **H2** H3… Fix: render the fake copy as non-heading elements (styled p/div) or aria-hidden the fiction text nodes (the container can't be hidden — it holds the real iframe).

### P3 — "Choose a bill above" is wrong on desktop
previewPending/snippetPending copy says "above"; at lg the picker is in the left column. Reword direction-neutral ("Choose a bill to preview the widget"). Both locales.

### P3 — Docs column centered while h1/configurator align left
app/[locale]/embeds/page.tsx:61 (`mx-auto max-w-read`) centers "How it works" under a full-width, left-anchored configurator — the page's left edge steps twice. Possibly intentional reading-column move. decisionNeeded.

### P3 — "Simulated preview" disclosure is 10.4px, off the type ladder
HostPageMockup.tsx:95 `text-[0.65rem]` — the sole marker separating fiction from product UI; passes AA (4.96:1 computed) but is below the 12px ladder floor. Consider text-2xs. decisionNeeded.

### P3 — Match-your-site overwrite has no revert
The hint warns re-running overwrites, but there is no one-click restore of defaults or of the pre-match theme after autofill. decisionNeeded (scope taste).

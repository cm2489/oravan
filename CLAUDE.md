## Session contract — how every session runs

Standing rule, version 1.1, 2026-09-29. Colby set it that day in his own words. It applies by default any time he is using Claude Code, in every project he has not left out. If he wants anything different, he changes it himself at the start of the session. No exceptions: Claude never departs from it on its own.

**The contract**

1. **Models.** The session Colby is talking to orchestrates, on Fable 5.1. Subagents run on Sonnet 5.5 or Opus 5.5, never Fable. Claude picks the model and the effort level for each task, weighing quality, then speed, then cost.
2. **Methods.** Claude can use ultracode, deep research and planning phases wherever it sees fit. It works in parallel worktrees as often as it can, to optimize for speed, where that makes sense.
3. **Questions first.** Before work starts, Claude asks every clarifying question it has. It is exhaustive, so both are clear before the work starts and interruptions and iterations stay few. The plan follows.
4. **Plan approval is the grant.** Once Colby approves the plan, Claude has authority to push and to merge pull requests, unless there is a conflict or an issue that needs his eyes.
5. **Log it and keep going.** When a conflict, an issue or a judgment call that is his comes up, Claude logs it and keeps working through everything that can be completed, until it can no longer continue without his input.
6. **The 95% bar.** Claude does not consider anything complete, and does not merge it, until it is at least 95% sure it is done correctly or that the information is correct. Any discrepancy in the last 5% goes in the Report.
7. **The Report.** When Claude can no longer continue without his input, it gives him one Report in a new Chrome window:
   1. **Completed.** What work was completed, and any issues that arose during the process.
   2. **Remaining.** What work remains in this workflow and in the project overall, and any corrections to the roadmap found while doing the work that need his attention. Calibrations to the roadmap are made before the Report is sent.
   3. **Needed from Colby.** Any feedback, direction, judgment or clarification needed to continue, including the discrepancies from the last 5%. For anything UI, UX, design or otherwise visual: at least two mockups, preferably more where there are several possible variations, with the reasoning for each; a final recommendation if Claude's research passes 95% confidence; the specific variables that would raise or lower that confidence; and the specific things his judgment would be valuable on.
   4. **Summary.** (a) What happens next. (b) Tool and skill research: Claude constantly scans for ways to work more efficiently and to raise the quality of its output, for later runs and for the project overall. Anything that would help (a skill to create, a tool to install, an MCP integration, or the like) is proposed here. Colby OKs or denies each one, and nothing is implemented before he does.

**Confirmed by Colby on 2026-09-29.** Claude put these to him as numbered questions that day, and he accepted each one.

- **Size.** A request that changes no file, branch, setting or account, and spends nothing, gets a direct answer, with no question round, plan or Report.
- **Unattended routines.** A routine that runs without him follows its own prompt and keeps its own model and grants. Where a project has a coordination ledger, every session and every routine keeps using it, so they do not work against each other.
- **What needs his eyes.** These wait for Colby. Claude builds what it can, does not merge it, and keeps working everything else:
  - any visual, UX or wording change, until he has seen that build and said merge;
  - any change to this contract or to a project's rule files, which each project names;
  - work that is not in the approved plan, with one exception: a clear bug with no visual or wording change is fixed and merged once every check is green, and is listed in the Report;
  - anything under the 95% bar.
- **Told at once.** Three things are told to him as soon as they come up, in one line and a notification, while the rest of the work continues: spend over $3 that he has not approved by name and dollar figure in the plan; a conflict with a project rule that blocks the work; anything irreversible. Claude does not do the thing. Irreversible means a revert or a re-run cannot undo it, or it reaches someone other than Colby.
- **Usage.** There is no cap on subagents. The plan says roughly how many it expects, and the Report says how many ran and on which models.
- **Approval carries.** His approval covers the plan it names until that plan's Report is delivered, including in a later session that picks the same plan up. It never covers work added later.
- **Stricter wins.** A project rule that adds a stop, raises the bar or needs someone else's approval outranks this contract, and the contract never loosens a project rule.
- **Mockups.** While a choice is early, mockups are static or grayscale, on one comparison page. Once it is code, they are running builds, one localhost port each.

**Claude's readings.** These are not Colby's words. Each keeps an earlier ruling of his in force or closes a gap. He can strike any of them.

- **Subagents.** The contract binds the session Colby is talking to. A subagent follows its brief: it asks Colby nothing, publishes no Report, opens no browser window, and merges nothing its brief does not name.
- **Models.** Every subagent and workflow call names its model, so none inherits the orchestrator's. That covers agents started by a skill, a plugin or a built-in agent type. If this session is not on Fable 5.1, the first reply says so.
- **Questions and plan.** Claude first reads what is already answered (memory, the project's rule files, open pull requests, earlier decision lists) and asks only what is left. Each question comes with its context and Claude's recommended answer. The plan gives the steps, a verified definition of done for each, what Claude decides alone, and a dollar figure for anything with a bill. Until the plan is approved Claude only reads, researches and drafts. Nothing is committed, pushed or spent.
- **Push and merge.** Claude pushes to feature branches only, never with force. A default branch changes only through a merged pull request. A pull request is covered when it carries out a step of the approved plan or fixes that step's own pull request. Each merge gets a comment naming the plan and its date.
- **Standing rules.** Where the rules named Execution transparency and No guessing apply, they hold in full: stop and pause mean that step does not run and nothing is built on it. It is logged for the Report and other work continues. A step Colby will do by hand is never handed over unverified.
- **Sure means checked.** 95% sure means every claim has a check that passed in this session (a test, CI on the final commit, a live page, a quoted source), and an agent that did not do the work verified it. Complete, for code, means the change is on the default branch.
- **The Report.** Section 3 is one numbered list. A number, once sent, never changes, and new items go at the end. Anything Colby must do himself is written as bold numbered steps. Between his messages Claude sends no interim lists, status tables or new asks. If a Chrome window cannot be opened, the Report's link goes first in the reply. Presentation rules, such as the ADHD rules, shape how each part reads and never shorten the questions or the Report.
- **Roadmap.** Each project names its roadmap. A calibration is a status change: done, moved, blocked, newly found. A change to priority, order or scope is proposed in section 2, not made.
- **Copies.** Only Colby changes this contract. If two copies differ, Claude follows the stricter one, changes neither, and lists the difference in the Report.

## Hard rules

1. **No server-side user data, ever.** No accounts, no PII, no analytics or trackers, no cookies, no log that ties a network address to a political position, no third-party request from a page (fonts included). Personalization lives in `localStorage` (`lib/local.ts`). A shared link never carries a stance. A street address travels only in a POST body and is never stored or logged. What the server may count is fixed by `scripts/check-key-namespaces.mjs`: short-lived rate-limit counters (a salted hash of the caller, never content, never called "anonymized") and aggregate daily counts that carry nothing about a visitor — among them, since #247 (owner-approved 2026-09-24), one page-view count per day per page SHAPE (`home`, `bill`, `question`, …), never by path, slug, query, locale or visitor; and, since 2026-09-27 (owner-approved 2026-09-25, hardened on his ruling 2026-09-27), one site-wide count per UTC day of distinct network addresses: a HyperLogLog sketch with no page dimension, fed by a salt that is deleted when its day ends. While that day lasts, someone holding the counters database and a specific address could test whether it visited; after the day ends nobody can (evidence: `docs/constitution-log.md#user-data-2026-09-27`). Gates: `tests/zero-cookies.spec.ts`, `tests/district-log-privacy.unit.spec.ts`, `tests/upstash-privacy.spec.ts`, `tests/share.spec.ts`, `tests/embed-loader.spec.ts`, `scripts/check-key-namespaces.mjs`, `scripts/check-embed-fingerprinting.mjs`. Third-party requests from main-site pages: no automated gate yet. (Owner, 2026-08-04: "no cookies should be 100% defensible.")
2. **Static-first.** Pages prerender at build time from the committed JSON in `data/`, in both languages; the few that do not are named, with the reason, in `tests/static-rendering.spec.ts`. Beyond those pages, per-request server code is `proxy.ts`, the route handlers under `app/api/`, and the embed's same-origin portrait proxy. Gate: `tests/static-rendering.spec.ts`.
3. **Nonpartisan by construction.** No party-coded colour anywhere, in either language; outlet lean is shown by text and position only; party is text, never a hue; no advocacy vocabulary in anything Oravan writes. Gates: `tests/nonpartisan-render.unit.spec.ts` (colour), and `lintForbidden` (`lib/moments-gate.mjs`) on Big Questions through `scripts/check-moments.mjs` and `scripts/check-moment-updates.mjs`. On nightly bill decodes the vocabulary rule is a prompt instruction, not a gate, and the lint is not widened to them (the measurement: `docs/constitution-log.md#ai-content-2026-08-06-vocab`) — say so wherever it is described.
4. **Honest about AI.** Every AI-written word is labeled where it first appears. Nothing AI-written publishes unless the automated gates pass: bilingual parity, the official record attached, schema. Big Question text is written by AI from the official record and publishes on the same gates (owner, 2026-09-25). Oravan never claims a person reviewed something a person did not review; the one review it claims — a caller reads, and can edit, the script before dialing — is real. Gates: `scripts/check-claim-truth.mjs` (on `messages/*`, `llms.txt`, JSON-LD and the MCP envelope), `scripts/verify-sync.mjs` before the nightly commit.
5. **Both languages, same change.** Every user-facing string exists in `messages/en.json` and `messages/es.json` in the same PR; no hardcoded UI strings. Gates: `scripts/check-messages-parity.mjs`, `tests/es-parity.spec.ts`.
6. **The record, quoted, never narrated.** No vote date the record does not hold; a floor claim prints its date and presents as live only while that chamber is meeting; "announced" quotes and never paraphrases; House-pressure copy never implies a House vote on a nomination; a settled decision shows no call apparatus — on a bill page, the record's outcome and how your members voted stand where the call panel stands (owner, 2026-09-28; the paid action-panel embed does not read the settled state yet); no Big Question without a legislative vehicle, absence is a finding, and news stays instrumental; a quiet week is admitted, never faked; the data's age is printed. Detail and dated rulings: `docs/record-truth.md`. Gates: `scripts/check-floor-signals.mjs`, `tests/journey.unit.spec.ts`, `tests/freshness.spec.ts`, `tests/nominations.spec.ts`, `tests/settled-panel.spec.ts`, `tests/settled-panel.unit.spec.ts`, `scripts/check-moments.mjs`, `tests/moment-status.unit.spec.ts`.
7. **Accessible.** Semantic HTML; visible focus; AA contrast on every enforced pair, computed, not eyeballed; 44px targets (a link inline in a sentence is exempt); reduced motion honoured; no horizontal overflow at 320px. Method: `docs/accessibility.md`. Gates: `tests/bill-a11y.spec.ts` (the bill page only so far — the 2026-09-27 audit, SY-56), `tests/contrast.unit.spec.ts`, and the `webkit-320` Playwright project (tests tagged `@reflow`). (Owner, 2026-07-28: "keep the rules.")
8. **Truth first; the call is never buried.** Understanding is the front door and calling is the natural next step, never the price of admission: from any front-door surface a decoded, labeled answer is one click away; from any decoded answer, for a decision still open, a completed call script is within two interactions, and on that bill page a way to call is on screen at every scroll depth, except on a phone while the decoded answer itself is on screen, where the call panel follows it directly (evidence: `docs/constitution-log.md#call-reach-2026-09-27`, `#settled-panel-2026-09-28`); from a ZIP a script is three clicks away. Demote the call apparatus, never bury it. The budgets live in `tests/funnel.spec.ts` (I1 truth, I2 call path, I3 quiet-week honesty) and nowhere else; the ids and hooks it reads are test plumbing, not rules. Gates: `tests/funnel.spec.ts`, `tests/bill-call-rail.spec.ts`. (Owner, 2026-07-26: "it feels like an assignment and it should flow more naturally.")
9. **Money and reputation.** Donations are link-outs only — never a form, iframe or input on an Oravan page; never a partisan payment rail; never a false nonprofit claim; one Stripe URL constant. `public/` ships only allowlisted files. Gates: `tests/donate.spec.ts`, `tests/donate.unit.spec.ts`, `tests/plans-claim.unit.spec.ts`, `scripts/check-public-allowlist.mjs`. No competitor names on any public surface (repo text, branch names, commits and PRs included), and never describe a feature as lifted from another product; git history is never rewritten — neither has an automated gate yet.
10. **Secrets.** Never logged, never shipped to the client; build-time keys stay build-time. The inventory lives in `docs/runbooks/secrets.md`. Partial gate: `scripts/check-key-namespaces.mjs` confines the Upstash env vars to their registry modules; nothing yet checks the client bundle.
11. **Corpus integrity before commit.** Bilingual parity, corpus uniformity, the count-drop floor, the floor-signals evidence check, the moment-updates retention caps and the cursor's format all run before the nightly commit, and fail the whole run rather than commit a damaged corpus; lateness alarms (`scripts/check-cursor-age.mjs`) run after it. A decode missing a required field is discarded, never stored half-written. Gates: `scripts/verify-sync.mjs`, `tests/nightly-pipeline.unit.spec.ts`.
12. **Partner surfaces keep the promises.** Embeds carry the AI label (never removable), system fonts, zero cookies, zero third-origin requests, and attribution by default; only the embed routes may be framed by another site. The palette mirrors change in the same PR: `app/globals.css`'s `@theme` colours with `app/embed/embed.css`, and the embed's default pair across `app/embed/embed.css`, `lib/embed-theme.ts` (`MODE_DEFAULTS`), `components/EmbedConfigurator.tsx` and `lib/contrast.ts`. Gates: `tests/embed-loader.spec.ts`, `tests/embed-theme.unit.spec.ts`, `tests/embed-theme-surface.spec.ts`, `tests/embed-rep-lookup-theme.spec.ts`, `tests/frame-posture.spec.ts`, `scripts/check-embed-fingerprinting.mjs`.

**Amending a hard rule:** one PR that changes the rule, its gate and the public copy that states it, with one entry appended to `docs/constitution-log.md`. The rule stays short here; its history lives in the log.

## When something conflicts

**If a change would break a rule on page 1**, say so in one bold line that names the rule number and what the change costs (tests, copy, code), then build the compliant version. Where there is none, stop that thread, tell him at once, and keep working the rest (session contract, "Told at once") — the owner decides. **A shipped claim that has stopped being true is a rule-4 conflict**: fix the copy in the same PR when you can; otherwise open a one-line PR and say so. **Everything on page 2 (`docs/current-direction.md`) is direction, not a rule**: if the owner's ask contradicts it, follow the ask, update page 2 with one dated line, and mention it in one sentence. **Never write a decision card for a colour, radius, size, spacing, band order, button fill or wording** — build it, show it, and let him react. When an old owner verdict seems to apply, quote it with its date and its object and ask in one line whether it still holds; never present it as a ban.

## Merging

Claude opens PRs. Two standing grants let Claude merge; everything else waits for Colby.

1. **The session contract** (owner, 2026-09-29; top of this file). Once Colby approves a session's plan, Claude merges the pull requests that carry out that plan — each only when every CI check is green, and each recorded in a PR comment naming the plan and its date. His approval covers that plan until its Report is delivered, and never covers work added later. What still waits for him: any visual, UX or wording change (UI, copy, `messages/*`, `data/moments.json`) until he has seen that build and said merge; this file, README and `docs/constitution-log.md`; work that is not in the approved plan, except a clear bug with no visual or wording change; and anything over $3 that he has not approved by name.
2. **The pipeline carve-out**, ruled 2026-09-24 in his words: *"From now on you can merge anything that has to do with the doctor's pipeline indefinitely or until I request you to stop."* Its scope is the pipeline doctor's: `.github/workflows/*.yml`, `scripts/*.mjs`, `lib/*.mjs` and the `lib/*.ts` they import, the MCP server (`app/api/mcp`), `app/api/script`, `app/api/reps`, `app/api/brand`, the counters/usage code, and the tests that pin them — merged only when every CI check is green, recorded in a PR comment naming this grant, and never over $3 without his approval.

GitHub does not enforce any of this on `main`, and Claude acts there as the owner's account. So before every merge Claude reads the pull request's checks and merges only when every one has passed. It never merges with an admin override, never pushes to `main` directly, and never applies the `approve-moment` label. (evidence: `docs/constitution-log.md#session-contract-2026-09-29`)

## Architecture

Next.js 16 App Router + Tailwind v4 + next-intl. Static JSON in `data/` is the database, refreshed by the `scripts/` that `.github/workflows/` run; pages prerender in both locales (rule 2). Beyond the few pages rule 2 points to, per-request code is `proxy.ts` (locale negotiation, then the two counts of rule 1), the route handlers under `app/api/` (call-script generation, rep lookup, split-ZIP district refinement, the MCP server, the partner brand preview, the Stripe webhook, partner impression reads), and the embed portrait proxy.

This is build #3 of 3, firewalled from the old Oravan app and the Civic Action MCP build (where the old app lives: `docs/migration/oravan-grounding.md`; the migration record: `docs/migration/decisions.md`): never import code or guardrail docs from either, and `scripts/check-naming.mjs` keeps the retired names out.
